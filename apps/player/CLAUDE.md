# Player

- Angular 22 standalone + signals, PWA. OneDrive MP3 player, no backend.
- Auth: `@azure/msal-browser` v5 (lazy-loaded) redirect flow, authority `common`, scope `Files.Read`, client ID in `src/app/config.ts` (empty = "not set up" screen). Redirect URI = document base URI; in a silent-renew iframe/popup `main.ts` only runs `broadcastResponseToMainFrame` (v5 needs it, else `block_iframe_reload`/`timed_out`).
- Graph calls in `src/app/onedrive/onedrive.service.ts`; playback uses `@microsoft.graph.downloadUrl` from a plain item GET (`$select` drops it on personal OneDrive; fallback: `/content` blob), cached 45 min, next track prefetched, one retry on audio error.
- Library = list of sources (`src/app/sources.ts`, localStorage `player.sources`): each OneDrive account (MSAL multi-account, `homeAccountId`) and each device folder is a top-level folder; path[0] is the source. Source settings open in a `<dialog>` (name, remove; OneDrive also `root` = top folder chosen via pick mode, `picking` in history state; device folders have no root). Last location `player.location`; queue saved in `player.session` (tracks carry `source` + `path`, so one queue mixes sources) and restored paused after reload (audio URL resolved only on Play). Track rows are not clickable; an add icon queues the track and the play icon (`playNow`) inserts the track at the current position and plays it (the current track is dropped only if it already started; no dedupe; tapping in the queue dialog just jumps); folder rows have the same two buttons (queue the folder non-recursively; play inserts the whole folder the same way); queue dialog from the player bar ("Clear queue" keeps only the current track playing). Old single `device` handle migrated on start.
- OneDrive listings cached in IndexedDB `folders` keyed `sourceId/folderId` (`folder-cache.ts`).
- Device folders (`src/app/device/device.service.ts`): File System Access handles in IndexedDB `handles` keyed by source id, permission re-requested on tap; fallback `webkitdirectory` input, session only. Both services expose `children(sourceId, folderId)` + `downloadUrl(sourceId, id)`. `npm run demo` swaps in `onedrive.service.demo.ts` (two demo accounts, sample tree, generated tones) via angular.json `demo` configuration.
- Folder and source navigation is pushed to browser history and the URL (`?path=` JSON of `[id, name]` pairs, `&pick=1` in top-folder pick mode; `locationToUrl`/`locationFromUrl` in `sources.ts`); the URL is not rewritten while it has a hash, so MSAL redirect responses stay intact.
- Queue logic pure in `src/app/player/queue.ts`; audio + Media Session in `player.service.ts`. Tabs sync over BroadcastChannel `player`: the tab that last started playing is leader (claim with timestamp), others mirror its state/time and forward controls as commands; leader sends `bye` on pagehide.
- Installed PWA uses Window Controls Overlay (`display_override`): header moves into the title bar (`titlebar-area-*` env, `app-region: drag`, controls `no-drag`) and `theme.ts` sets `meta[theme-color]` to the page background while the overlay is on.
- Signature colour `#7048e8` (violet). Themes auto/light/dark/eink (`theme.ts` copied from Tuner: auto switches to eink on `(update: slow), (monochrome)`); eink = white, black borders, no shadows or animations. Texts EN/CS in `src/app/i18n.ts`. Prettier: tabs, double quotes, width 120.
